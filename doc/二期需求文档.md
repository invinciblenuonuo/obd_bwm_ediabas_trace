# OBD Logger 二期需求文档：实时数据定时采样与落盘

> 关联文档：[需求文档.md](./需求文档.md)（一期）、[项目背景.md](./项目背景.md)、[../README.md](../README.md)
> Job/测量值定义的权威来源：[材料/MEVD174K.b1v](./材料/MEVD174K.b1v)（MEVD174K.prg 完整反编译 BEST/2 源码）

## 1. 总目标

在一期"链路打通 + 车辆基础信息"的基础上，将程序扩展为真正的**数据记录器（logger）**：
对发动机实时运行数据（转速、温度、负荷、增压、Lambda、点火等）进行**定时采样**，**实时显示**并**落盘为 CSV 文件**。
支持**从车辆上电未打火（KL.15 ON）到打火启动的完整过程**连续记录。

链路（同一期，已验证）：

```text
本程序 → api32.dll → EDIABAS(7.3.0) → MEVD174K.prg → K+DCAN(COM6) → E84 N20 DME
```

## 3. 采样通道（已对 b1v 核实）

### 3.1 核心 Job：`STATUS_MESSWERTBLOCK_LESEN`

一次调用即可**按名称**读取最多 **42 个**测量值（KWP2000 `$2C` 动态定义标识符 + `$21` 读取）：

| 参数 | 类型 | 说明（译自 b1v 注释） |
| ---- | ---- | -------------------- |
| `MODE` | string | `JA`/`ein`：在 ECU 中**重新定义**测量值块后读取；`NEIN`/`aus`：按 ECU 中**已存定义**读取（取值表 MESSWERTEMODE） |
| `MESSWERT` | string（动态参数） | 测量值名称，1~42 个，取自 `MESSWERTETAB.ARG`；每个名称对应一个 `STAT_*` 结果 |

结果：`JOB_STATUS`（OKAY/ERROR…，沿用一期检查逻辑）、各测量值对应的 `STAT_*_WERT` 结果、原始电报。

**参数传递约定（实现期首日实车小验）**：多个动态参数预期按 EDIABAS 惯例以分号连接为一个 para 字符串，形如
`"NEIN;INMOT;ITKUM;IVKMH"`；首次调用用 `"JA;…"` 定义测量块，后续循环用 `"NEIN;…"` 复用定义（更快）。

### 3.2 测量值目录表 `MESSWERTETAB`

b1v 行 4900 起，每行一条：`ARG, ID, RESULTNAME, INFO(描述), EINHEIT(单位), LABEL(A2L名), L/H, DATENTYP, NAME, MUL, DIV, ADD`
（换算：`物理值 = 原始值 × MUL ÷ DIV + ADD`；**Job 返回的已是换算后物理值**，EINHEIT 可直接写入 CSV 表头）。
全表估计数百至上千条，**实现期首个任务即用脚本从 b1v 全量导出该表**（见 FR-2-9）。

### 3.4 只读边界说明（红线符合性）

- `STATUS_MESSWERTBLOCK_LESEN` 本体为读操作；`MODE=JA` 时用的 `$2C`（DynamicallyDefinedLocalIdentifier）是把"动态标识符定义"写入 ECU **RAM**（断电即失、无持久化、非编码/编程），属于诊断标准流程（INPA 模拟量视图同样如此），认定为只读边界内。
- 若评审对此有异议：可只用 `MODE=NEIN`（读 ECU 已存定义）作为保守模式，代价是测量块定义不可控。
- 其余候选 Job（`STATUS_DAROL*` 固定数据集等）均为 `LESEN`（读）类。
- **严禁**（b1v 已列明的写/复位/编程类）：`*_SCHREIBEN`、`*_AUFTRAG`、`FS_LOESCHEN`、`*_RESET`、`FLASH_*`、`DIAGNOSEPROTOKOLL_SETZEN`、`PRUEFSTEMPEL_SCHREIBEN`、`ABGLEICHWERTE_SCHREIBEN`、`ENERGIESPARMODE`、`SLEEP_MODE` 等。

## 5. 架构设计（一期 NFR-3 的复用兑现）

```text
ObdLogger.exe
├── Ediabas/（一期封装层，原样复用：EdiabasClient / NativeMethods / 结果模型 / 异常体系）
├── Vehicle/（一期业务层，原样复用：ident + VIN 两阶段）
└── Logging 二期新增
    ├── Sampler.cs        采样循环（唯一持有 EdiabasClient 的线程！）
    ├── SampleConfig.cs   采样清单配置加载/内置默认
    ├── CsvWriter.cs      CSV 创建/逐行写入/flush/关闭
    └── LiveDisplay.cs    控制台就地刷新显示
```

**线程模型（关键约束）**：

- EDIABAS 句柄为单实例资源，**所有 API 调用必须串行在"采集线程"上**；禁止多线程并发调 API。
- 采集线程：定时触发 → 一次 Job 调用取回全部测量值 → 快照入队（lock-free/阻塞队列）。
- 显示线程与 CSV 线程：从队列取快照分别渲染/落盘；采集不被显示或 IO 阻塞（对应脑暴"采集数据不显示 log、多开线程"）。
- `Ctrl+C` → 置停止标志 + `apiBreak`（沿用一期机制），采集线程收尾后退出。

**采样时序与速率预期**（KWP2000 over K+DCAN 实测量级）：

- 单次 Job 调用开销 ≈ 0.1~0.5s（一期实测 ident ~0.06s，测量块含多字节电报会更慢）。
- 目标稳态采样率 **1~2 Hz**（可配 `--rate`，上限 5 Hz，实际以 ECU 响应为准；达不到时不堆积、不报错，按实际速率记录并纳入统计）。
- 时间戳以采样发起时刻计（`DateTime.Now`，毫秒）。

## 6. CSV 输出格式

```csv
# OBD Logger 二期  车辆: E84 N20  SGBD: MEVD174K  VIN: LBVUG7100EMD09858  开始: 2026-09-22 10:00:00
Time,RPM,VehicleSpeed,ECT,BoostActual,LambdaActual,IgnitionTiming,...
[ms],[1/min],[km/h],[°C],[hPa],[-],[°KW],...
2026-09-22 10:00:00.123,0,0,87.5,1013.2,1.00,-9.0,...
2026-09-22 10:00:01.245,812.5,0,87.5,1018.6,0.99,6.75,...
```

- 头两行注释（`#`）：车辆/配置元信息（VIN 取自一期两阶段读取，失败则留空）。
- 列顺序 = 配置文件顺序；缺失/失败样本写空字段；分隔符逗号；小数点用点（InvariantCulture）；UTF-8 无 BOM（Excel 兼容：中文显示名置第二行单位行之前的方案会破坏 Excel 公式兼容性——故显示名用英文/拼音列名，中文说明放注释行）。

## 8. 验收标准

| 编号 | 场景 | 通过条件 |
| ---- | ---- | -------- |
| AC-2-1 | 接车、点火 ON、发动机 OFF | `log` 模式启动成功，控制台实时显示，CSV 持续写入；转速=0；退出码 0；进程可 Ctrl+C 干净退出 |

| AC-2-7 | 回归 | 一期命令（默认、`--ecu`、`--job`、`--para`、`--verbose`）行为与一期验收一致 |

## 10. 二期明确不做（Out of Scope）

- 故障码（DTC）读取与清除（三期；FS_LESEN 为只读但属三期范围，清除为写操作另行评估）
- 实时图表/GUI（三期评估）
- 任何写入、复位、编程、刷写操作（含 C_FG/AIF/C_C 的 SCHREIBEN/AUFTRAG 变体）
